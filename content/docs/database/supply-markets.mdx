从 ecoinvent、openLCA 或 SimaPro 转向 TianGong LCA 时，从业者最常遇到的两个疑问是：**“为什么库里找不到 `market for electricity` 这样的市场过程？”** 以及 **“系统自动匹配上游并生成结果过程，是不是意味着它能按需动态合成市场数据集？”**

本页把 TianGong LCA 的上游供应连接逻辑、计算算例、生成物边界与排查方法一次讲透。

> **核心结论一目了然**
>
> - **没有独立的 `market` 数据集类型**：TianGong 不像 ecoinvent 那样预先编制与“生产过程”平行的 `market activity` 数据集。未手动连线的上游投入，在求解阶段通过**隐式区域供应组合（implicit regional supply mix）**按规则自动寻找供应方。
> - **不是“按需动态合成数据库”**：模型保存、发布或数据聚合生成的都是有明确输入版本的**物化计算产物**（如结果过程和 Calculation Bundle），并非按每次查询凭空合成虚拟市场数据集。
> - **自动连接不等于自动代表性**：系统不宣称采用归因（attributional）或后果（consequential）命名系统模型，也不能自动保证选中供应方的年份、技术路线或本地采购比例符合您的研究要求；凡对供应链代表性敏感的研究，都应核查诊断明细或改用显式建模。

## 一、先用“1 度工业用电”看懂两种思路的差别

假设您正在建立一个工厂生产过程，其中一条投入是“消耗 1 kWh 工业用电”，但手头没有电厂直供数据：

- **在 ecoinvent v3 中**：您通常会直接链接一个名为 `market for electricity, medium voltage` 的**独立市场数据集**。这个数据集由数据库团队事先建好，里面已经写死了各国/各区域电网的发电结构、跨境进口、输电损耗以及配套电网基础设施，并拥有自己的 UUID 和版本号。
- **在 TianGong LCA 中**：平台上没有这种专用的 `market` 数据集类型。如果您在模型画布中**手动连线**到某个具体电网或电厂过程，就按您指定的单一供应方计算；如果您把这条投入留作**未显式连接的技术圈需求**，求解器会在构建计算快照时，实时从合格的已发布过程中筛选出同流、同区域的参考产出过程，并按年供应量/年产量加权分摊这份 1 kWh 需求。

理解了这个区别，就能看懂后面所有规则、算例与报错提示。

## 二、模型画布编辑器与求解快照的边界

在日常操作中，请务必分清**“模型画布编辑器里的显式连线”**与**“求解快照里的隐式供应组合”**，两者的规则并不相同：

| 对比维度 | 模型画布编辑器（显式连线） | 求解快照引擎（隐式区域供应组合） |
| --- | --- | --- |
| **适用场景** | 您在网页端手动拖入过程并画线连接上下游 | 对未显式闭合的技术圈输入自动补齐背景供应链 |
| **多供应方处理** | **禁止同一条输入流同时连向多个上游过程**；触发后会报 `MULTIPLE_PROVIDERS` 并停止本地计算 | 允许按默认规则 `split_by_process_volume` 将一条需求按权重分摊给同一地理层级内的多个合格供应方 |
| **是否保存为新数据集** | 您手动连好的供应链结构会作为生命周期模型保存（见[在平台中保存与复用模型结果](/zh/docs/overview/data-relationships/)） | **不回写为新的 `market` 过程**；仅作为本次计算快照的矩阵系数与诊断记录存在 |
| **排查入口** | 画布连线校验与[系统建模 FAQ](/zh/docs/faq/system-models/) | 计算结果页的覆盖率与连接诊断明细（见[LCIA 计算与结果查看](/zh/docs/user-guide/lcia/)） |

> 如果真实业务中某原料确实由 A、B 两家工厂按 60% / 40% 共同供应，请不要在画布中直接把两家工厂同时连到同一条输入上（会触发 `MULTIPLE_PROVIDERS`），也不要为了通过校验而删除其中一家；正确做法是专门建一个代表“采购组合”的中间过程，按 0.6 和 0.4 列出两种投入再向下游供应。

## 三、隐式区域供应组合的完整路由步骤

当求解器采用默认多供应方规则 `split_by_process_volume` 构建技术矩阵 `A` 时，每一条尚未显式闭合的产品或废物需求，都严格按以下五步顺序确定供应方及权重：

```text
第 1 步：准入筛选与有符号流匹配
        仅开放数据(state_code = 100)及授权下的本人草稿(0)可入池；
        仅匹配精确同流(Flow UUID + 已解析版本)、方向相反、且为对方定量参考的交换
   ↓
第 2 步：生命周期模型防重算检查（version-exact-lineage-gate-v1）
        阻止同一生命周期模型的结果过程与其内部组成过程、或历史版本结果被混在一起重复计算
   ↓
第 3 步：同模型优先硬过滤（model_id）
        若消费过程隶属某模型，且存在合格同模型供应方，则只在该模型内部选择（优先级高于地理和年产量）
   ↓
第 4 步：确定供应区域并按 5 级地理阶梯向下查找
        区域来源：交换自身 location -> 消费过程 location -> unspecified
        地理阶梯：本地/次国家 -> 同国家 -> 同区域 -> 全球 -> 其他（命中首个非空层级即停）
   ↓
第 5 步：在命中层级内按年供应量/年产量加权分摊
        取正值 annualSupplyOrProductionVolume；缺失或非正时回退为固定权重 1.0，再归一化使权重之和恒为 1
```

### 第 1 步：谁有资格成为供应方

并不是平台上看得见的每一条过程都能进入自动供应池：

- **发布状态准入**：公开计算仅接纳已正式发布到开放数据的过程（`state_code = 100`）。只有当您以登录身份显式启用个人草稿计算模式（`public_plus_owner_draft`）时，您本人的草稿过程（`state_code = 0`）才会额外进入本次计算的候选池。经正式发布流程归档的只读派生结果过程（`state_code = 120`）及其他预留状态（`101..199`）**永远不会**被自动拉入供应池，以免把聚合结果当成普通单元过程反复套算。
- **三类流的分工**：产品流（Product）与废物流（Waste）进入技术矩阵 `A` 参与上下游平衡；基本流（Elementary）直接进入生物圈矩阵 `B` 参与环境影响计算；其他流（Other）仅作说明保留，不进入矩阵。
- **有符号流量与唯一参考端口**：求解器统一将输入记为负号（`Input = -1`）、输出记为正号（`Output = +1`），并以每个过程的定量参考交换作为基准项（归一化为 `+1` 或 `-1`）。自动路由**只接受**同时满足三个条件的候选交换：① `(Flow UUID, 已解析版本)` 与需求流完全一致；② 符号与需求流相反；③ 是供应过程的**定量参考（quantitative reference）**交换。
- **非参考联产品绝不自动入池**：如果某个过程顺带产出了一份同流副产品（非参考输出），即使写明了数量或分配系数，也不会自动成为该流的供应方。若全库只有非参考候选，诊断会明确报告 `rejected_non_reference_only`。

### 第 2 步：生命周期模型防重算检查

在实际建库中，一个生命周期模型既保存了构成它的若干单元过程，也可能伴随生成了汇总后的结果过程。如果两者碰巧都以同一种产品作为定量参考，直接按年产量混拼就会导致严重重复计算或边界错乱。

因此，在进入地理和产量筛选前，引擎会先运行精确版本的模型谱系检查（`version-exact-lineage-gate-v1`）：

- 若本次计算请求的根节点已经明确指定了该生命周期模型对应的结果过程，则该结果过程独占此连接，不再与其内部组成过程或旧版本结果混在一起。
- 若多个候选之间存在模型谱系重叠，但请求上下文没有给出明确的绑定依据，系统会**主动中止该条边的自动连接**，并报告 `lineage_overlap_requires_binding`，绝不擅自用年产量或均分来“猜边界”。

### 第 3 步：同 `model_id` 优先硬过滤

当消费过程归属于某个生命周期模型（带有 `model_id`），且前两步筛出的合格候选中至少有一个来自**同一个 `model_id`** 时，候选集合会被**直接硬性收窄到这个同模型子集**：

- 这是一条**硬过滤规则**，不是加分项，优先级高于地理远近和年产量大小。
- 只要同模型内有合格供应方，模型外的过程哪怕距离更近、产量更大，也不会被混入该输入。
- 只有同模型内完全没有合格候选时，系统才会退回更宽的合格过程池去寻找背景供应。

需要说明的是，同模型分组表达的是数据提供方预先划定的内部供应范围，它并不等同于针对每一条交换单独指定了采购合同比例。

### 第 4 步：供应区域来源与 5 级地理阶梯

锁定候选范围后，引擎先判断这条需求“希望从哪里采购”（供应区域锚点），按如下优先级取值：

1. 该条交换自身填写的 `exchange.location`（例如某江苏工厂明确标注该原料采购自山东 `CN-SD`）；
2. 若交换未填位置，则继承消费过程本身的 `location`；
3. 若两者都未填写，则标记为 `unspecified`（未指定地区）。

随后，引擎在候选集合中按严格顺序逐级查找，**一旦某个层级找到至少一个合格候选就立即停止**，绝不向下兼并，也绝不跨层级比较年产量：

1. `local / subnational`（本地 / 次国家，如具体省份或州）
2. `same country`（同国家）
3. `same region`（同区域，如大区或洲级）
4. `global`（全球）
5. `other`（其他地区）

### 第 5 步：层级内按年产量加权与 `1.0` 回退规则

在最终命中的那一级地理层级内，每个候选供应方的份额按如下公式计算：

```text
若候选的 annualSupplyOrProductionVolume 为有限正数：
    原始权重 w_i = annualSupplyOrProductionVolume_i
否则（缺失、为空、非数字或 <= 0）：
    原始权重 w_i = 1.0

最终份额 share_i = w_i / sum(w)
```

请牢记两条核心数学性质：

- **只分摊归属，绝不改变总需求**：同一条需求的所有供应方份额之和恒等于 `1`（`sum(share_i) = 1`）。系统只会把 100% 的需求拆给各供应方，绝不会因为供应方数量多而把消耗量放大或缩小。
- **`1.0` 回退只是兜底权重，不是声明产量为 1**：它仅用于防止缺少产量字段的合格过程被静默踢出，但每次触发回退都会在快照诊断中明确计数，提醒您检查份额是否合理。

## 四、三个具体算例：把抽象规则算明白

### 算例 1：地理层级、年产量加权与 `1.0` 回退的实际影响

假设江苏（`CN-JS`）一家工厂消耗 **100 kWh** 工业用电，未手动指定电厂。合格开放数据池中共有三个生产该电力的单元过程：

- 过程 A（`CN-JS`）：年产量 `300,000`
- 过程 B（`CN-JS`）：年产量 `100,000`
- 过程 C（`CN`）：年产量 `5,000,000`

1. **正常情况（地理阶梯优先于年产量）**：引擎先匹配到 `local / subnational` 层级（`CN-JS`），发现过程 A 和 B 非空，因此**立刻停止**，过程 C 虽然全国产量高达 500 万，但属于更粗的 `same country` 层级，**不会入选**。最终份额为：过程 A 占 `300,000 / 400,000 = 75%`（75 kWh），过程 B 占 `100,000 / 400,000 = 25%`（25 kWh）。
2. **一有一缺（警惕极端悬殊的份额）**：若过程 B 漏填了年产量，过程 B 的原始权重回退为 `1.0`，而过程 A 仍为 `300,000`。最终份额会变成：过程 A 占 `300,000 / 300,001 ≈ 99.9997%`，过程 B 仅占 `0.0003%`——几乎等同于只选了过程 A。
3. **两者均缺（自动退化为均分）**：若过程 A 与过程 B 都没有填写年产量，两者都回退为 `1.0`，最终份额变成各占 `50%` / `50%`。

> 这正是为什么在解读结果时，**必须查看诊断面板里的 `1.0` 回退计数**：一个漏填的年产量字段，就可能让两个本地供应方的份额在 50%/50% 与 99.9997%/0.0003% 之间剧烈摇摆。

### 算例 2：同模型优先与生命周期模型防重算

假设您打开了“模型 A”（包含自备热电联产过程与化工合成过程）：

- **同模型优先**：模型 A 中的合成过程需要蒸汽。虽然外部开放数据库里有地理位置相同、年产量大得多的公用蒸汽过程，但模型 A 内部自带一个合格的蒸汽产出过程，引擎会先用同 `model_id` 硬过滤锁定模型 A 自己的蒸汽过程，**不会混入外部蒸汽**。
- **防重算拦截**：假设“模型 B”产出了 1 吨目标原料，库中同时存在模型 B 的最终结果过程 `R(B)` 以及其内部组成过程 `U(B1)`，两者恰巧都以同一产品流作为定量参考。如果您的计算请求没有明确指定要绑定 `R(B)`，防重算检查会拒绝把 `R(B)` 和 `U(B1)` 混在一起加权，而是标记 `lineage_overlap_requires_binding`，提示您明确绑定边界。

### 算例 3：废物流的符号等价规则

在 LCA 建模中，不同数据库对“送去处理的废物”写法常有差异：有的写成废物输出，有的写成负值输出或废物输入。TianGong 采用统一的有符号流量运算（`Input = -1`，`Output = +1`）：

- 某产废过程写出 **废物输出 `+1000 kg`**（有符号值 `+1000`），表示产生了一笔正值废物待处理需求。
- 若焚烧或填埋处理过程的参考交换写成 **废物输入 `+1000 kg`**（有符号值 `-1000`，归一化符号 `-1`），或写成 **废物输出 `-1000 kg`**（有符号值 `-1000`，归一化符号 `-1`），两者在数学上**完全等价**，都能与 `+1000 kg` 的产废需求形成异号平衡。
- 反之，若另一个过程把该废物流写成 **废物输出 `+1000 kg`**（归一化符号 `+1`），它只能去平衡负值废物需求，不会被错当成上述正值废物的处理厂。

## 五、TianGong 到底“生成”了什么，没有生成什么

业界常把“保存模型自动算结果”误解为“动态数据库会按查询实时拼出新的市场数据集”。下表把平台真正会生成的计算产物和明确不存在的能力一一划清：

| 机制 / 产物 | 何时触发 | 生成了什么 | 是否持久化为数据集 | 身份是否稳定可引用 |
| --- | --- | --- | --- | --- |
| **求解快照（Solver Snapshot）** | 运行模型或过程级背景计算时 | 稀疏技术矩阵 `A`、生物圈矩阵 `B`、供应权重与诊断信息 | **否**（计算期内存/快照态，绝不写回新 `market` 数据集） | 每次快照记录输入版本与配置指纹，可追溯计算条件 |
| **模型保存产物** | 在网页端保存生命周期模型时 | 依据模型分配规则物化的主产品/次级产品子模型过程与结果过程 | **是**（与模型共同保存在当前工作区） | 绑定到模型与对应过程的 `(UUID, version)` |
| **正式发布物化（Release Materialization）** | 数据产品管理与发布流水线执行发布时 | 冻结边界下的三元组：单元过程 `U(P)`、派生结果过程 `R(P)`（`state_code = 120`）、模型 `M(P)`（遵循 `resolved-one-hop-aggregated-background.v1`）以及带清单哈希的 Calculation Bundle | **是**（严格隔离的只读归档产物，不回流污染普通供应池） | 使用确定性 `UUIDv5` 规则与精确版本号，配合 SHA-256 与读回核验 |
| **数据聚合结果** | 对多个过程按权重或产量汇总为单一代表过程时 | 聚合后的结果过程（`R(P)`） | **是**（显式保存的结果记录） | 拥有明确版本与来源谱系 |
| **按需动态合成 market / 参数化虚拟过程** | **不存在** | **无**（平台不根据外部查询参数实时动态生成并持久化新的虚拟市场或参数化过程） | 不适用 | 如需特定区域或年份的市场组合，必须手动建过程并显式发布 |

## 六、分配（Allocation）与系统边界策略

阅读求解配置或结果报告时，经常会同时看到“分配”与“边界策略”两个概念，它们分别管不同的环节：

- **分配管“归自己多少”，路由管“找谁来供”**：过程内部的分配系数先作用于各条非参考交换，算清当前参考产品应分摊多少原料消耗与排放；路由权重随后只负责把已经确定的原料需求分摊给上游合格供应方。两者顺序固定、互不替代。
- **三种显式边界策略**：当某些技术圈需求在库中找不到任何合格供应方（即出现未闭合边）时，求解快照支持三种显式策略，且策略名称与未闭合明细都会写入配置指纹与诊断报告，绝不静默吞掉：
  - **`closed`（默认生产口径）**：严格要求所有非零技术圈需求都闭合；只要存在未闭合需求，快照就无法通过完整性就绪检查。
  - **`open`**：允许未闭合的技术圈需求留在系统边界之外并继续求解，同时逐条列出未闭合交换清单。
  - **`cutoff`**：允许按显式截断边界省略未闭合需求并输出逐边截断证据。平台面向核查的完整性检查（Scope Closure）固定锁定为 `cutoff`，以便完整暴露所有缺失供应方的证据清单。

| 诊断信号 | 实际含义 | 建议处理方式 |
| --- | --- | --- |
| `MULTIPLE_PROVIDERS` | 模型画布中，同一过程的同一条输入流手动连了两个及以上上游过程 | 检查画布连线，清理误连；若真实供应链确为多源采购，新建一个组合过程显式写明各供应商比例 |
| `rejected_non_reference_only` | 库里有产出同一流的过程，但全部都是非参考副产品，没有任何过程把它设为定量参考输出 | 为上游过程修正定量参考输出、补充以该流为主产出的单元过程，或在显式模型中定义联产品归属 |
| `lineage_overlap_requires_binding` | 候选中同时出现了同一生命周期模型的结果过程与其组成过程（或旧版本结果），引擎无法判断该取哪一层 | 在请求中明确绑定目标结果过程，或检查并理清相关生命周期模型的引用边界 |
| **`1.0` 回退计数大于 0** | 命中地理层级中有部分候选过程缺失或填写了非正的年产量/年供应量 | 点开选中供应方列表核对实际占比；若因“一有一缺”导致权重严重偏斜，应补全权威年产量或改用显式建模 |
| **地理层级回退到 `global` / `other`** | 在本地、同国家、同区域均未找到合格过程，只能退而求其次选用全球或其他地区数据 | 判断该投入对总结果是否敏感；若为关键高影响原料，优先补充本地数据或显式指定替代地区 |
| **存在未闭合边（`closed` 阻塞或 `open`/`cutoff` 明细）** | 某条产品或废物需求在当前准入范围内找不到任何合格供应方 | 检查流的 UUID、版本号与输入/输出方向是否正确；确认上游过程已发布为开放数据（`100`），或在本人草稿模式下核对草稿完整性 |

## 八、什么时候自动连接够用，什么时候必须显式建模

| 使用场景 | 隐式区域供应组合是否够用 | 推荐做法 |
| --- | --- | --- |
| 早期热点筛查、教学演示或次要低贡献辅料 | **通常够用** | 使用自动连接，但仍应抽查地理层级与 `1.0` 回退计数 |
| 需要可重复引用、有独立 UUID 和版本的“区域消费组合” | **不够用** | 新建独立的组合过程并显式写明上游来源与占比 |
| 涉及跨境运输、长途物流、电网输配损耗或装卸损耗 | **不够用** | 隐式组合**不自动附加运输与损耗**；必须在过程清单中显式加入运输与损耗交换 |
| 研究限定了特定基准年份、特定工艺路线或真实采购合同比例 | **不够用** | 显式连线锁定具体上游过程与精确版本（参考[部分终止系统建模案例](/zh/docs/data-collection/case-introduction/model-building/)） |
| 涉及需要精细处理的联产品或废物闭环回收 | **不够用** | 先完成清晰的过程分配或构建显式生命周期模型，避免副产品被自动池忽略 |
| 正式 EPD、产品碳足迹认证或 ISO 14044 对外对比声明 | **不建议单独依赖** | 对主要贡献环节全部显式建模并归档版本清单，同时保留完整诊断与覆盖率证明（见[版本、许可与引用](/zh/docs/database/versions-citation/)） |

## 九、ecoinvent v3 `market activity` 与 TianGong 机制全景对照

| 对比维度 | ecoinvent v3 | TianGong LCA |
| --- | --- | --- |
| **数据集形态** | 独立的 `market activity` 数据集（与 `transforming` 转化过程分离） | 无独立的 `market` 数据集类型 |
| **区域组合构成** | 预先编制的区域消费组合，包含国内生产、进口、运输距离与方式、损耗及多级 `market groups` | 计算期动态路由：防重算检查 → 同模型硬过滤 → 区域锚点 → 5 级地理阶梯 → 年产量加权（缺失回退 `1.0`）；不含自动运输与损耗 |
| **系统模型体系** | 四套命名系统模型（Cut-off、Cut-off EN15804、APOS、Consequential），Consequential 下 market 代表边际消费组合 | 无命名系统模型；默认路由规则 `split_by_process_volume`；边界策略 `closed` / `open` / `cutoff`；不宣称归因或后果 |
| **画布建模体验** | `market` 作为常规节点直接拖入连接 | 画布禁止单输入连多上游（`MULTIPLE_PROVIDERS`）；隐式组合仅发生在求解快照中 |
| **可引用身份** | 每个 `market` 数据集拥有独立 UUID 与版本号 | 隐式组合不持久化为独立数据集；如需稳定身份须手动创建并发布组合过程 |
| **代表性责任** | 由数据库记录系统模型假设，研究者挑选匹配版本与模型 | 明确声明自动连接不保证时间、技术与地理代表性，研究者须核查诊断结果或显式建模 |

如需继续对比其他主流 LCA 数据库与格式转换规则，请阅读[跨库比较与格式互通](/zh/docs/database/comparison/)与[数据库总览](/zh/docs/database/overview/)；关于归因平均供应组合与后果边际市场响应的完整方法论，可延伸阅读天工 LCA 知识库[市场响应](https://prism.tiangong.earth/zh/docs/book/market-boundaries-and-response/)。
