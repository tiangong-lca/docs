Whether you are writing an academic paper, preparing a product carbon footprint (CFP) or Environmental Product Declaration (EPD), or maintaining long-lived team models, **reproducibility and compliance depend on pinning exact dataset versions, verifying license terms, and citing sources cleanly.**

This page brings together every rule covering dataset identity, versioning, lifecycle states, licensing, and citation templates in TianGong LCA.

> **At a Glance**
>
> - **Exact identity is the pair `(UUID, version)`**: A dataset name or bare UUID is never enough to reproduce a calculation. Always record `UUID@version` (for example `<uuid>@01.01.000`).
> - **No automatic per-dataset DOI minting**: Native stable identifiers are `(UUID, version)` and `common:permanentDataSetURI`. If a dataset comes from a published paper or report with a DOI, that DOI lives in its linked **Source** record.
> - **Open visibility does not mean unrestricted commercial reuse**: Open Data is freely viewable and computable for signed-in users, but redistribution and commercial rights always follow the exact version's own license and copyright fields.
> - **Machine integrity checks are not scientific certification**: Release receipts, SHA-256 checksums, and readback checks prove byte-level consistency with source records—they never substitute for scientific fitness review or third-party ISO/EPD verification.

## 1. Dataset Identity and Three-Part Versioning (`XX.XX.XXX`)

In TianGong LCA and TIDAS, every record is uniquely identified by **`UUID`** plus its three-part **`version`**, written compactly as **`UUID@version`**.

### 1. Version Structure and Typical Progression

Versions follow the ILCD/TIDAS `XX.XX.XXX` pattern. New datasets created on the platform start at **`01.01.000`**:

| Example version | Segment changed | Typical reason |
| --- | --- | --- |
| `01.01.000` | Initial release | Default version when creating or first importing a dataset |
| `01.01.001` | Patch / build segment | Draft iteration, formatting adjustment, or internal incremental edit |
| `01.02.000` | Minor segment | Adding source references, correcting individual exchange amounts, or expanding metadata |
| `02.00.000` | Major segment | System-boundary change, full reference-year refresh, process-route change, or major methodological update |

### 2. "Create Version" vs. "Copy Data"

When revising or deriving from an existing dataset, choose the right action—they behave very differently:

| Dimension | Create Version | Copy Data |
| --- | --- | --- |
| **Where to find it** | Row actions → **All Versions** → **Create Version** | Row actions → **Copy Data** |
| **Effect on UUID** | **Keeps the exact same UUID** and auto-increments the version number | **Generates a brand-new UUID**, resetting the version to `01.01.000` |
| **Lineage record** | Links back automatically via `common:referenceToPrecedingDataSetVersion` | Creates an independent record outside the original version history |
| **When to use it** | Fixing errors, updating reference years, or refining the same process/dataset | Using an existing dataset as a template for a different process, region, or project |

### 3. Default List Behavior and Downstream Pinning

- **Lists show the latest visible version by default**: Platform tables and search show each UUID's newest visible version. To inspect or cite an earlier version, open **All Versions** on the dataset row (see [Data Platform Overview](/en/docs/user-guide/data/) and [Data Usage](/en/docs/user-guide/data-use/)).
- **Downstream models stay pinned to exact versions**: Lifecycle Model nodes, solver snapshots, and public catalog pages all lock to exact `(UUID, version)` pairs. Publishing `01.02.000` **never silently alters** an existing model pointing to `01.01.000`.

## 2. Permanent URIs, Public Catalog Links, and DOI Policy

### 1. Permanent Dataset URIs (`common:permanentDataSetURI`)

Every TIDAS record stores a canonical `common:permanentDataSetURI` aligned with LCDN detail paths:

| Object type | Default permanent URI template |
| --- | --- |
| **Process** | `https://lcdn.tiangong.earth/datasetdetail/process.xhtml?uuid=<uuid>&version=<version>` |
| **Flow** | `https://lcdn.tiangong.earth/datasetdetail/productFlow.xhtml?uuid=<uuid>&version=<version>` |
| **Lifecycle Model** | `https://lcdn.tiangong.earth/datasetdetail/lifecyclemodel.xhtml?uuid=<uuid>&version=<version>` |
| **Source** | `https://lcdn.tiangong.earth/datasetdetail/source.xhtml?uuid=<uuid>&version=<version>` |
| **Contact** | `https://lcdn.tiangong.earth/datasetdetail/contact.xhtml?uuid=<uuid>&version=<version>` |
| **Flow Property** | `https://lcdn.tiangong.earth/datasetdetail/flowproperty.xhtml?uuid=<uuid>&version=<version>` |

### 2. Public Catalog URLs and Withdrawals

- In the [TianGong LCA Public Data Catalog](https://www.tiangong.earth/en/lca-database), every public version has a shareable canonical page accessible without signing in.
- If a published version is later withdrawn or restricted due to corrections or rights changes, it is removed from the public catalog. Always keep the `UUID@version`, provider name, and **access date** alongside the URL.

### 3. DOI Policy

- TianGong LCA **does not automatically mint a separate DOI for each dataset**.
- To reference a TianGong dataset unambiguously, cite **`UUID@version`**, its canonical catalog URL, and **`common:permanentDataSetURI`**.
- When a dataset draws from a peer-reviewed article, statistical report, or external dataset that carries a DOI, that DOI is recorded in the linked **Source** object and should be cited alongside the platform record.

## 3. Dataset Lifecycle and State Machine (`state_code`)

The platform controls every record's journey from draft to review, publication, and isolated archiving through database-level `state_code` values:

```text
  My Data: Draft (state_code = 0)
        │  Submit for Data Review
        ▼
  Under Review (state_code = 20, edit-locked) ── Rejected ──▶ Back to Draft (0)
        │  Approved & published
        ▼
  Published Open Data (state_code = 100, read-only) ── Further edits via Create Version ──▶ New Draft (0)

  Isolated tracks:
  • Formally archived release Result Processes ──▶ state_code = 120 (read-only archive; excluded from ordinary modeling/routing)
  • Third-party commercial catalog listings    ──▶ state_code = 200 (metadata only; cannot be linked into models)
  • Built-in curated learning examples         ──▶ state_code = -1  (practice only; excluded from Open Data counts)
```

| State (`state_code`) | Meaning & location | Editable? | Public catalog visibility | Calculation & modeling eligibility |
| --- | --- | --- | --- | --- |
| **`0`** | **Draft** (My Data) | Editable by author | Not visible | Excluded from public runs; usable only when the author explicitly runs in owner-draft calculation scope |
| **`20`** | **Under Review** ([Data Review](/en/docs/user-guide/data-review/) queue) | **Locked** | Not visible | Excluded from public runs; awaits assignment by `review-admin` and review by `review-member` |
| **`100`** | **Published Open Data** (Open Data & Public Catalog) | Read-only (create a new version to revise) | Visible | **Sole eligible public process pool** for standard calculations; searchable, linkable, copyable, and exportable |
| **`120`** | **Published Derived Result Process** (formal release archive) | Read-only | Excluded from standard public process browse | Strictly isolated from ordinary modeling reads, routine exports, and automatic supply routing; accessed only via authorized release receipt/readback paths |
| **`200`** | **Commercial Data** (Commercial Data space) | Read-only metadata | Visible (metadata only) | **Cannot be linked into models or computed on the platform**; contact the provider for licensing |
| **`-1`** | **Curated Examples** (signed-in example area) | Read-only for ordinary users | Excluded from Open Data catalog | For onboarding and practice only |

> **Keep runtime state separate from TIDAS publication metadata**: Inside the dataset JSON, `common:workflowAndPublicationStatus` (such as `Working draft`, `Data set finalised; entirely published`, or `Withdrawn`) captures ILCD/TIDAS bibliographic status. Actual platform permissions, visibility, and solver admission are always governed by `state_code`.

## 4. Licensing, Ownership, and Redistribution Matrix

Before reusing, modifying, or redistributing any TianGong LCA dataset, inspect four fields in **`publicationAndOwnership`** on the exact version:

1. **`common:referenceToOwnershipOfDataSet`**: Identifies the legal owner of the dataset (not necessarily the platform operator).
2. **`common:copyright`**: Boolean (`true` / `false`) indicating whether copyright applies.
3. **`common:licenseType`**: Controlled TIDAS enumeration with five values (see table below).
4. **`common:accessRestrictions`**: Plain-text conditions, attribution requirements, redistribution limits, or link to full license terms.

### Permission Guide for the Five `common:licenseType` Values

| `common:licenseType` value | Plain meaning | What to verify before commercial use or redistribution |
| --- | --- | --- |
| `Free of charge for all users and uses` | Free for everyone across use cases | Check `copyright`, `accessRestrictions`, and attribution wording; preserve version and source citations |
| `Free of charge for some user types or use types` | Free only for specified groups or purposes (e.g., academic or non-commercial) | Verify whether commercial consulting, paid software bundling, or external disclosure falls within allowed uses |
| `Free of charge for members only` | Free only for members of a designated organization, consortium, or project | Non-members must not reuse or redistribute without confirming membership or contacting the rights owner |
| `License fee` | Paid license required | Obtain formal permission from the rights owner before using or redistributing full inventory data |
| `Other` | Custom license terms | Read `common:accessRestrictions` carefully and confirm ambiguous terms directly with the owner |

### Channel-Specific Compliance Notes

- **Open Data**: Reviewed and openly available for browsing, modeling, and export, but **individual open datasets may carry different `licenseType` and copyright terms**. Always verify per dataset and review the portal [About the Data](https://www.tiangong.earth/en/methodology) guidance.
- **Commercial Data**: Displays descriptive metadata and provider contacts only, without full inventory tables. To license commercial libraries such as HiQLCD, follow [Commercial Database Access](/en/docs/faq/commercial-database/).
- **LCDN (ILCD Node) Distribution**: ILCD packages fetched from the [TianGong Life Cycle Data Network (LCDN)](https://lcdn.tiangong.earth/) into openLCA or other software remain bound by the exact version's license and copyright clauses.

## 5. Four Ready-to-Use Citation Templates

Copy the template matching your deliverable and replace the placeholders in angle brackets with your actual record details.

### Template A: Academic Paper or Technical Report (Single Dataset)

Aligned with the Public Data Catalog citation format:

```text
Data provider: <Provider Name> (when applicable). TianGong LCA Platform, dataset: <Dataset Name>, version <01.01.000>, identifier <uuid>@<01.01.000>, accessed <YYYY-MM-DD>, available at <Canonical Public Catalog URL or permanentDataSetURI>.
```

Example:

> Data provider: Tsinghua TianGong Team. TianGong LCA Platform, dataset: Coal-to-methanol production, version 01.01.000, identifier `8f3c2b10-0000-4000-8000-000000000001@01.01.000`, accessed 2026-10-15, available at `https://www.tiangong.earth/en/lca-database` (replace with the exact version detail URL or permanent URI in your report).

### Template B: EPD / Product Carbon Footprint Appendix Table

For audited appendices, list every key background dataset in a structured disclosure table:

| Dataset Name | Exact Identifier (`UUID@version`) | Geography & Reference Year | Data Space & License Type | Permanent URI / Canonical URL | Access Date |
| --- | --- | --- | --- | --- | --- |
| `<Dataset Name>` | `<uuid>@01.01.000` | `CN` / `2024` | Open Data / `Free of charge for all users and uses` | `https://lcdn.tiangong.earth/datasetdetail/process.xhtml?uuid=<uuid>&version=01.01.000` | `2026-10-15` |

### Template C: Model Calculations, LCIA Results, and Release / Calculation Bundles

When citing calculated LCI or LCIA indicators rather than raw unit inventories, record four additional items (see [LCIA Calculation & Results](/en/docs/user-guide/lcia/)):

```text
Model / source process: <Name> (<uuid>@<version>)
LCIA method: <Method name & version, e.g., TianGong 25-method static EF bundle, non-regional default profile>
Coverage & boundary note: <Confirm whether all elementary flows matched factors; list any uncovered flows; state explicit vs. implicit supply linking>
Release provenance (when applicable): Release <release-id>, Calculation Bundle manifest hash <sha256-...>, computed/accessed <YYYY-MM-DD>
```

> **Important distinction**: Calculation Bundle manifest hashes, SHA-256 checksums, and release readback checks prove **byte-level integrity against source records**. They do **not** attest scientific fitness for your specific goal and scope, nor do they replace third-party ISO 14040/14044 or EPD verification.

### Template D: LCDN Downloads and Commercial Catalog Entries

- **ILCD datasets retrieved via LCDN**: Extend Template A by noting the channel as "TianGong Life Cycle Data Network (LCDN, [https://lcdn.tiangong.earth/](https://lcdn.tiangong.earth/))" together with the export or sync date.
- **Commercial Data catalog entries**: Cite metadata-only listings strictly as a catalog discovery reference—**never** imply that full inventories were computed inside TianGong. If you licensed full data separately from a commercial provider, cite that provider's official release and license directly.

For quick tips on attaching supporting documents during data entry, see [Sources & Citation FAQ](/en/docs/faq/sources-and-citation/) and [Database Overview](/en/docs/database/overview/).
