## Comment construire un modèle dans TianGong LCA ?

1. Créez ou sélectionnez les processus unitaires requis dans **Mes données → Processus**, en veillant à des entrées et sorties complètes.
2. Ouvrez **Mes données → Modèles**, cliquez sur `+` et ajoutez les processus au canevas.
3. Connectez les entrées et sorties, définissez le processus de référence et la quantité du flux de référence.
4. Enregistrez le modèle — voir [Créer mes données](/fr/docs/user-guide/create-my-data/#créer-un-modèle) pour le workflow complet.

## Que faire si l'enregistrement d'un modèle signale un processus de référence manquant ?

Si l'enregistrement affiche « The model is missing reference process information. Complete or
rebind the reference process, then try again. », le modèle courant ne dispose pas d'un
`referenceToReferenceProcess` utilisable. Retournez sur le canevas du modèle, confirmez que le
nœud utilisé comme processus de référence existe toujours, puis redéfinissez le processus de
référence et la quantité du flux de référence avant d'enregistrer.

## Que signifie le signalement de plusieurs fournisseurs pour une entrée lors de l'enregistrement d'un modèle ?

L'éditeur de modèles vérifie les connexions explicites du canevas. Si le même flux d'entrée d'un
processus est relié à plusieurs processus amont distincts, le calcul local de l'éditeur signale
plusieurs fournisseurs et s'arrête.

Vérifiez les connexions amont du flux d'entrée indiqué. Corrigez les connexions en double ou erronées
selon les relations d'approvisionnement réelles afin que l'entrée ait un seul processus fournisseur,
puis réessayez. Si le scénario réel nécessite plusieurs fournisseurs, déterminez d'abord comment
modéliser cette structure d'approvisionnement. Ne supprimez pas de relations réelles uniquement pour
réussir la validation.

Cette vérification concerne les connexions explicites dans l'éditeur. Le mix régional implicite
décrit ci-dessous concerne le choix des fournisseurs dans l'instantané du solveur ; il ne signifie
pas que l'éditeur prend en charge plusieurs connexions explicites de fournisseurs pour un flux d'entrée.

## Comment la plateforme choisit-elle les fournisseurs pour les entrées de produits ?

Lorsqu'un échange d'entrée de produit n'est pas explicitement lié à un fournisseur, TianGong LCA
utilise un mix régional d'approvisionnement implicite dans l'instantané du solveur.
`exchange.location` de l'entrée de produit sert d'abord de région d'approvisionnement. En
l'absence de localisation d'échange utilisable, la localisation du processus consommateur sert
d'ancre par défaut. Si le processus consommateur possède un `model_id` et que le même modèle
contient un fournisseur éligible de sortie de référence pour le flux de produit, le système
utilise d'abord ce sous-ensemble de fournisseurs du même modèle. Sans fournisseur de même modèle,
il revient au mix régional plus large. Le système choisit ensuite le meilleur niveau géographique
et pondère les fournisseurs de ce niveau par leur volume annuel d'approvisionnement ou de
production. La liaison automatique ne traite comme fournisseur éligible pour ce flux de produit
qu'une sortie de référence quantitative ; une sortie non-référence de même `flow_id` n'entre pas
automatiquement dans l'ensemble des fournisseurs au seul motif qu'elle possède un montant ou une
fraction d'allocation.

Cette répartition détermine quels fournisseurs portent la demande d'une entrée ; elle n'augmente
ni ne réduit le montant total de cette entrée. Si un fournisseur n'a pas de volume annuel valide,
le système le conserve avec une pondération positive par défaut et expose le repli dans la
couverture de l'instantané ou les diagnostics de liaison des fournisseurs. Si tous les candidats
de même flux sont des sorties non-référence, les diagnostics exposent l'entrée comme
`rejected_non_reference_only` ; réparez la sortie de référence, ajoutez des données de fournisseur
ou modélisez explicitement le processus de marché / coproduit.

## En quoi TianGong LCA diffère-t-il des autres plateformes d'ACV ?

| Aspect | TianGong LCA | Outils desktop traditionnels (SimaPro, GaBi, Umberto, openLCA, etc.) |
| --- | --- | --- |
| Gestion des données | Natif cloud avec collaboration d'équipe et workflows de revue | Principalement projets locaux ; collaboration souvent manuelle |
| Construction de modèles | Assembler des processus depuis des dépôts partagés ; publier vers les équipes | Généralement import ou maintenance de bases privées |
| Format des données | Utilise le schéma JSON ouvert TIDAS pour la transparence et l'intégration | Formats de bases propriétaires |
| Contrôle de versions | Brouillons, historique et suivi d'état intégrés | Dépend d'une gestion de fichiers externe |

## Puis-je interopérer avec d'autres logiciels ?

- **Export JSON** : téléchargez les jeux de données en TIDAS JSON, puis mappez les champs pour l'import dans d'autres outils.
- **Intégration MCP** : utilisez les [services MCP TianGong](/fr/docs/integration/mcp-lca-remote/) pour appeler des jeux de données depuis des applications externes.
- **Précautions** : les noms d'unités et définitions de propriétés peuvent différer entre systèmes ; prévoyez une étape de mapping ou de conversion.

Pour des intégrations sur mesure ou des besoins d'entreprise, contactez l'équipe TianGong pour
étudier les options de partenariat.
