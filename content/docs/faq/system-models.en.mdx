## How do I build a model in TianGong LCA?

1. Create or select the required unit processes in **My Data → Processes**, ensuring inputs and outputs are complete.  
2. Open **My Data → Models**, click `+`, and add the processes to the canvas.  
3. Connect inputs and outputs, set the reference process, and define the reference flow quantity.  
4. Save the model—see [Create My Data](/en/docs/user-guide/create-my-data/#create-a-model) for the full workflow.

## If saving a model reports a missing reference process, what should I do?

If saving shows “The model is missing reference process information. Complete or rebind the
reference process, then try again.”, the current model does not have a usable
`referenceToReferenceProcess`. Return to the model canvas, confirm that the node used as the
reference process still exists, then set the reference process and reference flow quantity again
before saving.

## What does it mean when saving a model reports multiple providers for one input?

The model editor checks explicit connections on the canvas. If the same input flow of one process
is connected to several distinct upstream processes, the editor's local calculation reports a
multiple-provider issue and stops.

Inspect the upstream connections of the indicated input flow. Correct duplicate or incorrect
connections according to the actual supply relationships so that the input has one supplying
process, then try again. If the real scenario needs several suppliers, first establish how to
represent that supply structure; do not remove real supply relationships merely to pass validation.

This check applies to explicit connections in the editor. The implicit regional supply mix below
describes provider selection in a solver snapshot; it does not mean the editor supports several
explicit provider connections for one input flow.

## How does the platform choose providers for product inputs?

TianGong LCA **does not provide standalone ecoinvent-style `market activity` datasets**. When a product input exchange is not explicitly linked to one provider, the solver snapshot applies an **implicit regional supply mix** (default rule `split_by_process_volume`): after numerical eligibility and the version-exact Lifecycle Model lineage gate, it routes by same-`model_id` hard filter → supply-region anchor (`exchange.location` before process location) → first non-empty geography tier → annual supply/production volume weighting (with a fixed `1.0` positive fallback). Automatic linking admits only quantitative reference outputs; if every same-flow candidate is non-reference, diagnostics report `rejected_non_reference_only`.

This implicit mix is a calculation-time routing policy—not a persisted market dataset—and does not automatically guarantee temporal, technological, or geographic representativeness. See [Supply Linking & Market Mechanism](/en/docs/database/supply-markets/) for the full routing order, diagnostics, and explicit-modeling criteria.

## How does TianGong LCA differ from other LCA platforms?

| Aspect | TianGong LCA | Traditional desktop tools (SimaPro, GaBi, Umberto, openLCA, etc.) |
| --- | --- | --- |
| Data management | Cloud-native with team collaboration and review workflows | Primarily local projects; collaboration often manual |
| Model construction | Assemble processes from shared repositories; publish to teams | Typically import or maintain private databases |
| Data format | Uses the open TIDAS JSON schema for transparency and integration | Proprietary database formats |
| Version control | Built-in drafts, history, and status tracking | Depends on external file management |

For structured comparisons with ecoinvent, ILCD/EF, USLCI, BAFU, AGRIBALYSE, and format conversion caveats, see [Cross-Database Comparison & Interoperability](/en/docs/database/comparison/).

## Can I interoperate with other software?

- **JSON export**: Download datasets as TIDAS JSON, then map fields for import into other tools.  
- **MCP integration**: Use the [TianGong MCP services](/en/docs/integration/mcp-lca-remote/) to call datasets from external applications.  
- **Caveats**: Unit names and property definitions may differ between systems; plan for a mapping or conversion step.

For bespoke integration or enterprise requirements, contact the TianGong team for partnership options.
