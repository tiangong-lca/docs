description: "Installer Flow Hybrid Search dans le projet et vérifier fichiers, environnement et connexion CLI."
---

Cette page prend `flow-hybrid-search` comme exemple. Un seul Skill installé au niveau du projet permet de comprendre son comportement. Ni le catalogue complet ni une clé serveur ne sont nécessaires.

## 1. Vérifier les prérequis

- Un client compatible Skills autorisant les commandes locales. Ce guide couvre Codex et OpenClaw ; une simple page de discussion ne peut pas exécuter ces scripts.
- **Exactement Node.js `24.19.0`** et **pnpm `11.24.0`**. Le lanceur actuel vérifie ces versions exactes ; toute version de Node 24 ne convient pas.
- Git et le réseau pour récupérer le dépôt Skills ; la première exécution télécharge aussi le CLI fixé.
- Un compte TianGong LCA et un dossier de projet local auquel vous autorisez l’IA à accéder.

Si Node.js ou pnpm manque, suivez [l’installation du CLI](/fr/docs/integration/cli/getting-started/). Ouvrez un terminal à la racine du projet de l’IA et vérifiez les commandes suivantes.

```bash
node --version
pnpm --version
git --version
```

## 2. Choisir un client et une installation

Codex :

```bash
pnpm dlx skills@1.5.23 add tiangong-lca/agent-skills --skill flow-hybrid-search --agent codex --copy --yes
```

OpenClaw :

```bash
pnpm dlx skills@1.5.23 add tiangong-lca/agent-skills --skill flow-hybrid-search --agent openclaw --copy --yes
```

Installez pour les deux seulement si vous utilisez les deux. `--skill` choisit le Skill, `--agent` le client et `--copy` copie ses fichiers d’exécution. L’installation est limitée au projet. `--yes` évite les confirmations : vérifiez donc source et nom avant de lancer.

## 3. Confirmer l’installation dans le projet

| Client | Dossier du Skill dans le projet |
| --- | --- |
| Codex | `.agents/skills/flow-hybrid-search/` |
| OpenClaw | `skills/flow-hybrid-search/` |

Vous devez trouver `SKILL.md`, `scripts/run-flow-hybrid-search.mjs`, `scripts/lib/cli-launcher.mjs` et `assets/example-request.json`. Ne copiez pas seulement `SKILL.md`. Gardez le `skills-lock.json` à la racine pour suivre l’installation et examiner les mises à jour ; ce n’est pas un identifiant de connexion.

Listez les installations du projet avec la commande suivante. Ouvrez ensuite le même projet dans le client IA, démarrez une nouvelle session et demandez explicitement `flow-hybrid-search`. Une installation enregistrée ne prouve pas le chargement dans la session actuelle ; voir [le dépannage](/fr/docs/integration/skills/troubleshooting/) si nécessaire.

```bash
pnpm dlx skills@1.5.23 list --json
```

L’installation vérifiée correspond au commit Skills `0a33db1df81f9bd3ce52d356178fa35adc40b67c`. Avec cet installateur, `skills.flow-hybrid-search.computedHash` dans `skills-lock.json` doit correspondre à la valeur ci-dessous. C’est une empreinte d’installation, pas une signature. Si elle diffère, revérifiez source et prérequis puis faites une simulation avant de reprendre les conclusions vérifiées de ce guide.

```json
{
  "computedHash": "e75673431b0adaae42c96a009bc52f82f82c22a1d269ca798158ab8b11eccd4b"
}
```

### Confirmer que le client a lu le Skill

Envoyez ce contrôle dans une nouvelle session. L’activité de lecture de fichiers/Skills doit montrer le `SKILL.md` correspondant, et la réponse expliquer « requête JSON → résultat de recherche de flux en lecture seule ». « Je peux le faire » ne prouve pas le chargement.

```text
N’exécute encore aucune commande métier. Confirme que tu peux lire le SKILL.md de flow-hybrid-search dans ce projet et indique le vrai chemin, les entrées nécessaires et les sorties.
Pour Codex : .agents/skills/flow-hybrid-search/SKILL.md ; pour OpenClaw : skills/flow-hybrid-search/SKILL.md. Lis seulement le chemin correspondant à ce client.
```

Sans trace de lecture ou si la découverte échoue encore, joignez explicitement le bon `SKILL.md` local et demandez au client de le suivre. S’il ne peut pas lire les fichiers du projet ou exécuter des commandes locales, utilisez le tutoriel CLI et ne déclarez pas le parcours Skills validé.

## 4. Se connecter soi-même au CLI

La recherche distante utilise la session locale privée du CLI. Vérifiez d’abord le statut. Pour `login-required`, connectez-vous dans un terminal de confiance et autorisez dans le navigateur ; ne transmettez pas de mot de passe ou de jeton à l’IA.

```bash
pnpm dlx --package=@tiangong-lca/cli@0.1.13 tiangong-lca auth status --json
pnpm dlx --package=@tiangong-lca/cli@0.1.13 tiangong-lca auth login
pnpm dlx --package=@tiangong-lca/cli@0.1.13 tiangong-lca auth doctor-auth --json
```

L’utilisateur système et l’environnement du script doivent accéder au même contexte de connexion. La Production officielle ne demande ni `.env`, ni identifiant client public, ni source CLI locale. Seuls les environnements personnalisés exigent une [configuration complète et cohérente](/fr/docs/integration/cli/authentication/). Les Skills ne conservent pas une seconde session OAuth.
